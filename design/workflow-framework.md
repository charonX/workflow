# 人机协作开发工作流 · 总框架 v0.1

> 状态：框架草案（2026-06-22，对标 `ref/gstack` 后成形）
> 定位：本框架 = 我们的**认知纪律内核**（"测试即契约"）装在一套 **gstack 式的操作骨架**上。
> 内核的逐条推导见 [`test-as-contract-workflow.md`](./test-as-contract-workflow.md)，本文是把它放进端到端流程的总装图。

---

## 0. 一句话定位

> **参考项目回答"流程怎么跑"，我们回答"凭什么相信跑出来的是对的"。**

两者正交、可叠加：gstack 等参考项目给了阶段、产物、技能、自治梯度、知识沉淀这套**操作骨架**；我们这套的价值在**认知纪律**——真理只向下流、纠错只向上回、测试是唯一契约、断言归人、REQ 是测试唯一出生地。把后者注入前者，就是本框架。

## 1. 与对标项目的分工

| 维度 | gstack 等已提供（直接借用） | 我们的内核补强（差异点） |
|---|---|---|
| 阶段编排 | 思考→设计→规划→构建→审查→QA→反思，可条件跳过 | 在其上叠"**双挡**"：探索期(无测试)/固化期(测试锁定)，并明确跨越线 |
| 规格产物 | requirements/prd/test-plan/tasks.md，验收命令必须可执行 | **REQ 带 ID + 测试反挂 REQ**，REQ 是测试**唯一出生地**（纯粹派，杜绝套件腐化） |
| 测试驱动 | TDD 红绿重构、单元自动提交、垂直切片 | **人不改代码、只改 REQ/断言**；缺陷/需求变更靠回溯 REQ **机械裁决** |
| 角色隔离 | 实现者 / 规格审查者 / 质量审查者 三角 | **实现者对测试只读 + 测试作者独立**，加抗特判（防 AI 刷绿灯作弊） |
| 审查 | 两轴 标准 + 规格 并行、22 种角色画像 | 对齐：行为对错=规格轴(机器)，观感好坏=人判(HTML 参照)，**主观不进测试** |
| 验收 | QA 场景驱动 健康评分 + 回归测试 + 异常可能性自调节 | 慢外门跑 E2E；状态翻转默认放行 + 反复翻转转阻断（见内核留账②） |
| 授权 | 自治梯度 L1/L2/L3（自治等级 1/2/3），配置化升级 | 门 1(签断言)/门 2(验观感)/逃生口(轮数上限) 的具体落点 |
| 知识沉淀 | 工程经验 / ADR / STANDARDS，两阶段加载 | 直接借用，暂不改 |

**结论：我们不重造骨架，只把骨架里"构建/纠错"那一段换成更严的纪律内核。**

## 2. 两条公理（贯穿一切）

```
真理只向下流：   PRD(意图) → REQ(验收标准) → 测试(可执行契约) → 代码(实现)
                上层是下层的"为什么"，下层是上层的"怎么验"；代码永远不是真理来源

纠错只向上回：   错在哪层，就回到"出错的最高那一层"修，绝不在低层就地打补丁
                代码不绿→循环内自修 | 测试漏场景→回REQ | 行为没依据→回PRD | 方向没想清→回一挡
```

违反第二条（看代码不对就直接改代码、看测试碍事就改测试）= 污染真理来源 = 整套失效。

## 3. 双挡模型（回应"PRD 不可能一次想清"）

```
━━━ 一挡 · 探索期（无 REQ、无测试，随便推翻，免费）━━━
   需求洞察(对抗式访谈) → 草稿 PRD(软) → HTML UX 原型：搭→看→推翻→再搭
   ← "看到才知道哪儿不对"的发现，绝大多数应发生在这里

━━━ 跨越线：某块"不再推翻 / 即将被别的东西依赖" ━━━
   把它从 PRD 结晶成带 ID 的 REQ + 验收标准 → 铺网上锁

━━━ 二挡 · 固化期（测试即契约，按已结晶 REQ）━━━
   测试作者写前置验收测试 →【门1 人签断言】→ 实现者自主磨到全套绿 →【门2 人验观感】
```

- 一挡可无限循环、零成本试错；HTML UX 是思考工具，不是最终实现。
- 二挡的回报恰恰是单人开发最缺的**回归安全网**——你越高频改，网越值钱。
- 错误用法：拿二挡的机器去锁一个还在动的需求 → 又贵又堵。

## 4. 阶段骨架（gstack 阶段 × 我们的纪律）

| 阶段 | 挡位 | 干什么 | 我们注入的纪律 | 借 gstack 的 |
|---|---|---|---|---|
| **思考** 需求洞察 | 一挡 | 对抗式访谈逼出隐含需求/边界/矛盾 | 访谈是产出 PRD 的方式；进固化前做"缺了啥"完整性体检 | 头脑风暴、多角色画像需求审查 |
| **设计** UX 探索 | 一挡 | HTML UX 原型快速迭代 | 双轨收割：行为→REQ文字，观感→HTML 当视觉参照挂 REQ | UI 设计 / UI 规格 / 原型契约 |
| **结晶**（跨越线）| → | 把稳定块写成带 ID 的 REQ + 验收标准 | REQ 是裁判、是测试唯一出生地 | tasks.md 的可执行验证形式 |
| **测试** 写靶子 | 二挡 | 测试作者从 REQ 派生前置验收测试 | 断言归人；测试作者 ≠ 实现者，权限互斥 | TDD 场景结构、垂直切片 |
| **门 1** | 二挡 | 人签字断言 | 不签不许实现 | （我们新增的硬门） |
| **构建** 自主实现 | 二挡 | 实现者对测试磨到全套绿 | 实现者对测试只读；内循环跑全单元兜回归；逃生口=轮数上限 | 单元自动提交、工作树隔离、日志 |
| **审查/QA** 慢外门 | 二挡 | 浏览器/App E2E + 观感验收 | 行为机器判 / 观感人判(门2)；状态翻转默认放行+反复翻转转阻断 | 两轴审查、健康评分、回归测试、异常可能性自调节 |
| **门 2** | 二挡 | 人验观感→过/判缺陷/判需求变更 | 都回流最高出错层，绝不手改代码 | （我们新增的硬门） |
| **反思** 沉淀 | — | 提炼可复用经验 | 暂直接沿用 | 工程经验/ADR/STANDARDS |

## 5. 角色与授权

**三个智能体角色（权限互斥）+ 人**

| 角色 | 能写 | 不能写 |
|---|---|---|
| 人 | REQ、断言、HTML UX | 不直接写/改实现代码 |
| 测试作者智能体 | 测试（脚手架） | 实现代码 |
| 实现者智能体 | 实现代码 | 测试（只读） |

**授权 = 门 + 梯度**：人在两端使劲（门 1 签断言、门 2 验观感），中段全自主；失败走逃生口（轮数上限→上报，不许自己改测试）。整体自治程度可借 gstack 的 **L1/L2/L3（自治等级 1/2/3）梯度**逐步上调（连续通过率达标才升级）。

## 6. 产物链与目录（借 gstack 的 `.aiassist/` 形态）

```
真理向下流的四层，落到文件：
  PRD          docs/ 或 .aiassist/stories/<id>/prd.md      （软，叙事）
  REQ          .aiassist/stories/<id>/requirements.md       （带 ID，验收标准）
  HTML 参照    ux/<flow>.html                                （挂在对应 REQ 上，观感基准）
  测试         tests/...（每个测试头部反挂 REQ-ID）
  代码         src/...
  知识沉淀     .aiassist/global/{engineering-lessons,architecture,STANDARDS}
```

关键不变量：**每个测试都能回溯到某条 REQ-ID**；REQ 变 → 挂它的测试标记过时待重生。

## 7. 定位声明：我们补的是"测试信任层"

**核心论点：**

> 这些参考项目不是没有测试——它们各有 TDD、QA、审查机制，甚至触及测试理论里的 "Oracle 问题"。它们缺的是：**把"什么算对"这个测试预言锚定在"人持有、且 AI 无法作弊"的断言上。**

**两种北极星的取舍（不是单纯谁更好）：**

| | 参考项目（gstack/superpowers/mattpocock） | 我们 |
|---|---|---|
| 北极星 | **吞吐**：AI 基本可信，给流程脚手架让它多出活、快出活 | **自主下的信任**：读不完 AI 的代码，凭什么敢信它对了 |
| 测试地位 | 下游**质量门** | 上游**契约（主干）** |
| 测试预言 | 文档 + AI 判断 | **人持有的断言** + AI 仅做脚手架 |
| 代价 | 放弃部分信任换吞吐 | 牺牲部分吞吐（人签断言）换"不读代码也敢信" |
| 适配 | 有 QA/能抽查的团队 | 单人/OPC——读不完，信任是真瓶颈 |

**我们的研究贡献**：不是"参考项目 + 更好的测试"，而是给这个领域补上它整体缺失的一层——**AI 自主下，如何把测试预言锚定在人持有、抗作弊的断言上**。

---

## 8. 我们比参考项目更严 / 参考项目有而我们可借

**更严（我们的差异化）：**
1. 人**绝不直接改代码**——纠错只走 REQ/断言（参考项目的 TDD 没强制这条）。
2. REQ 是测试**唯一出生地**，纯粹派杜绝套件腐化。
3. 缺陷与需求变更靠**回溯 REQ-ID 机械裁决**，不靠感觉。
4. 实现者对测试**只读**、抗特判，结构性防"刷绿灯作弊"。
5. **双挡 + 跨越线**显式化，主观/客观两条纠错回路分离。

**参考项目有、我们可后续借：**
- 自治梯度的**量化升级条件**（通过率/打回率阈值）。
- QA 的 **健康评分** 与 **异常可能性自调节**（防修复陷阱）。
- **知识沉淀的两阶段加载**（防上下文膨胀）。
- 多角色画像并行审查的具体编排。
